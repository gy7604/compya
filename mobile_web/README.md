# 휴대폰 웹 제어

## v2.0.23 야구공 아이콘

PWA192/512px와 Apple 홈 화면180px 아이콘을 야구공·재생 표시로 통일했습니다. 푸시에는 같은 컬러 아이콘과 별도96px 흰색/투명 배지를 사용합니다. SVG 원본은 `icons/`에서 관리하며 `npm run icons`로 PNG를 다시 만듭니다. 주요 그림은 maskable 아이콘의 중앙 안전 영역 안에 배치했고, 배지는 Android 흑백 처리에서도 봉제선과 재생 표시를 구분하도록 만들었습니다.

manifest·Apple 링크·푸시 아이콘 경로에 버전을 넣고 서비스 워커 캐시를 갱신했습니다. 기존 경로도 새 이미지로 응답합니다. 로그인·휴대폰 구독·인증 키·PC EXE는 변경하지 않습니다. 설치된 홈 화면 아이콘이 바뀌는 시점은 휴대폰의 갱신 정책에 따라 다르므로 실제 기기 확인이 필요합니다. PWA를 다시 열어 갱신한 다음 메뉴에서 테스트 알림으로 확인하세요. 사용자 수신 확인이 끝난 기존 푸시 전송 방식은 유지합니다.

## v2.0.22 화면 정리와 푸시 수정

상단 제목과 설치 안내 카드를 제거하고 시작·중지를 현재 상태 오른쪽에 세로로 배치했습니다. 알림 켜기/끄기/테스트, PC 재부팅과 로그아웃은 상단 메뉴에 모았습니다. 알림 기록에는 서버 접수·HTTP 거절·만료·연결 오류를 구분해 표시합니다. 테스트는 PC 매크로가 대기 중이어도 가능하며 서버 접수 완료와 실제 휴대폰 수신은 별개입니다.

v2.0.21의 `redirect: 'error'`는 Workers에서 요청 전 TypeError를 일으켰습니다. `manual`로 변경해 리디렉션을 따라가지 않고 응답 상태를 실패로 처리합니다. 로컬 workerd에서 수정 전 같은 오류를 재현했고 수정 후 합성 구독으로 FCM의410 응답을 확인했습니다. 합성 구독 검사는 실제 휴대폰 알림 수신 검증이 아닙니다. 실제 구독·인증 키는 보존하며 실패한 과거 알림을 자동 재전송하지 않습니다. 이 변경은 웹만 적용하므로 PC EXE를 다시 받을 필요가 없습니다.

PC의 V26Macro 안에 포함된 연결 기능이 HTTPS로 이 서버를 주기적으로 확인합니다. PC의 포트를 외부에 열거나 별도 원격 데스크톱을 설치하지 않습니다. 이 서버는 다른 앱의 Worker·D1·접근 설정과 분리된 `compya-mobile-control` 전용 Worker와 SQLite Durable Object 하나를 사용합니다.

휴대폰은 PC의 **휴대폰 웹 제어**에서 표시한 QR 또는 연결 암호로 로그인합니다. 내 휴대폰의 로그인 유지를 선택하면30일, 해제하면12시간이며 HttpOnly·Secure·SameSite 쿠키로 보관합니다. 연결 암호를 URL 쿼리나 로그에 기록하지 않습니다. QR의 fragment는 브라우저가 즉시 지우고 로그인 본문으로만 전송합니다. 익명 사용자는 경기 상태·화면·명령 API에 접근할 수 없습니다. 연결 암호와 QR은 본인 기기에서만 사용하세요.

시작·중지는 현재 PC의 모드와 일정, 모의 실행 설정을 그대로 사용합니다. 원격에서 금액·구매 조건·이미지·PC 파일·ADB 주소를 변경할 수 없습니다. PC의 게임 설정 확인 체크가 필요하며 지정된 LDPlayer0 (`127.0.0.1:5555`)만 허용합니다. 중지는 매크로만 멈추며 게임이나 플레이어를 종료하지 않습니다. 프로그램이 닫혔거나 PC가 잠들어 연결되지 않으면 명령을 받지 않습니다. 다른 실행 파일 두 개가 동시에 연결되면 기존 활성 인스턴스를 보호합니다.

명령은 현재 프로그램 실행에 묶여 30초 후 만료됩니다. PC에 먼저 저장한 명령 ID는 중복 실행하지 않으며, 실행 중 강제 종료로 결과가 불확실해진 명령도 자동 재실행하지 않습니다. 휴대폰에서 응답이 없을 때 명령을 자동 재전송하지 않습니다.

게임 화면은 휴대폰으로 보고 있을 때만 약5초 간격으로 360×640 JPEG를 전송합니다. 데스크톱·다른 앱 화면을 수집하지 않습니다. 서버는 화면을 영구 저장소에 쓰지 않고 최근30초 화면만 메모리에서 제공합니다. 상태는 마지막 PC 연결 시각을 표시하고, 오래된 화면은 현재 화면으로 보여 주지 않습니다. 시즌 수는 PC의 확인된 표시를 그대로 사용하며 추정하지 않습니다.

## 로컬 검증과 배포

`npm ci` 후 `npm test`, `npm run check`로 검사합니다. `.dev.vars`에는 검사용 `OWNER_KEY_HASH`, `AGENT_KEY_HASH`, `SESSION_KEY`를 넣고 `npm run dev`로 로컬 Worker를 실행할 수 있습니다. 실제 연결 암호·PC 설정·게임 화면을 소스나 검사 데이터에 넣지 않습니다.

실제 외부 접속 배포는 저장소 AGENTS.md의 승인 규칙을 따릅니다. 배포 전에 대상 Worker와 계정·플랜을 확인하고, 기존 앱의 Worker나 D1을 변경하지 않습니다. 두 연결 키는 PC에서 생성하고 Windows 사용자 DPAPI로 보호한 `mobile_control.json`에 보관합니다. 서버에는 두 키의 SHA-256 해시와 별도 세션 서명 키만 비밀 설정으로 등록합니다. `mobile_control.json`, 명령 처리 기록, 비밀 설정 파일은 커밋·배포 ZIP·공개 Release에서 제외합니다. 앱이 닫히면 연결 스레드도 끝나며 별도 Windows 서비스나 작업 스케줄러를 설치하지 않습니다.

무료 플랜의 한도 안에서 운영하도록 구성하며 유료 플랜으로 자동 변경하지 않습니다. 일반 대기 연결은10초, 보고 있을 때는3초 간격입니다. 기기 브라우저의 백그라운드 정책과 네트워크 상황에 따라 갱신이 늦어질 수 있습니다. 실제 LTE/5G 휴대폰 접속과 절전/재부팅 후 사용은 별도 실기기 확인 범위입니다.

## v2.0.20 PWA와 복원

메뉴의 앱 설치 또는 홈 화면에 추가를 사용합니다. 설치한 PWA에서 첫 로그인이 필요할 수 있습니다. 기존의 유효한 세션은 비공개 쿠키를 유지한 채30일 로그인으로 전환할 수 있고, 연결 암호는 기기 저장소에 저장하지 않습니다. 서비스 워커는 정적인 화면 파일만 캐시하며 API·사진·로그인 응답·조작 명령을 캐시하거나 오프라인 재전송하지 않습니다.

PC의 자동 연결 옵션은 현재 사용자 Run 항목 CompyaMobile 하나에 설치 경로와 --restore-session만 등록합니다. 별도 서비스·자동 Windows 로그인은 구성하지 않습니다. 시작 상태·모의/실제 설정·확인 상태는 비공개 startup_restore.json에 보존합니다. 수동 중지와 오류 종료 후에는 자동 경기를 다시 시작하지 않습니다. 실행 중 예기치 않게 PC가 종료된 경우 마지막 실행 의도를 이어받습니다. 중복 실행은 사용자 세션 뮤텍스로 차단합니다.

재부팅은 본인 로그인과 현재 PC에 묶인60초 유효 확인 절차 및 ‘PC 재부팅’ 문구 입력이 필요합니다. PC에서 명령을 확인한 뒤20초 동안 기다리며 그 안에 취소할 수 있습니다. Windows shutdown의 양수 /t가 강제 종료를 암시하므로 프로그램 안에서20초 대기한 후 /r /t 0으로 요청하며 /f는 사용하지 않습니다. 예약 취소 후 매크로는 중지 상태이며 시작 버튼으로 재개합니다. 실제 PC 재부팅 시험은 별도 승인 없이 실행하지 않습니다.

## v2.0.21 기록 수집과 서버 푸시

PC의 mobile_telemetry.json·mobile_facts.json 및 랭킹 일별 집계에서 제한된 구조의 자료만 수집합니다. 원본 로그·개인 알림 채널·구매 금액·화면 이미지는 푸시 판단 자료에 넣지 않습니다. 현재 UI가 마지막으로 확인한 시즌 수를144 완료로 추측하지 않습니다. 실제144번째 결과가 확인된 경우 시즌 ID별 완료 사실을 따로 보존하므로 다음 시즌 진입 후에도 전송할 수 있습니다.

서버는 최초 완료 기록을 과거 기준선으로 등록하고 이후 새 완료만 알립니다. 최근5분의 새로운 오류 기록은 첫 접속에도 처리합니다. 완료 기록은24시간 이내만 알림 대상으로 삼고, 랭킹 결과의 미집계분을 경기 수에 추정 합산하지 않습니다. 수집이 불확실한 경우 완료로 판단하지 않습니다. 사건 ID와 기기별 전송 상태를 영구 저장하여 반복 수집과 서버 재시작 후 중복 전송을 막습니다. 전송 결과가 불명확한 요청은 자동 반복하지 않으며 알림 기록에 확인 필요로 남습니다.

실행 중 연결이2분 끊긴 경우 Durable Object alarm이 휴대폰 페이지와 독립적으로 판단합니다. PC의 수동 종료/중지, 모의 실행, 예정된 재부팅에는 이 경고를 적용하지 않습니다. 연결 두절은 전원·프로그램 종료·인터넷 등 원인을 단정하지 않습니다. 중간 복구 시도는 기존 복구 정책을 유지하며 한도에 도달한 최종 실패를 알립니다.

PWA에서 **이 휴대폰에서 알림 켜기**를 직접 누를 때만 브라우저 권한을 요청합니다. iPhone은 홈 화면에 추가한 앱에서 사용합니다. 기기는 최대3개이며 각 기기에서 알림을 끌 수 있습니다. 테스트는1분에 한 번만 요청할 수 있습니다. 푸시 클릭은 항상 기존 모바일 제어 주소로 열립니다. 알림이 등록되기 전의 기록은 기록 화면에만 남고 새 기기에 소급 전송하지 않습니다. 실제 휴대폰 설치·권한 허용·휴대폰 알림 수신은 별도 확인 사항입니다.

표준 Web Push(aes128gcm와 VAPID)를 사용합니다. 구독 주소는 Apple/Google/Mozilla/Microsoft의 허용한 HTTPS 푸시 호스트만 받으며 리디렉션을 따라가지 않습니다. 푸시 수신 주소와 키는 소유자 전용 서버에만 저장하고 알림 조회나 로그에 반환하지 않습니다. VAPID_PRIVATE_KEY는 기존 Worker 비밀 설정에 등록하고 로컬 유지 관리 사본은 Windows DPAPI로 보호합니다. 기존 인증 키를 바꾸지 않으며 VAPID 키를 임의로 재생성하지 않습니다. 새 유료 플랜·FCM 개발자 프로젝트·다른 앱 리소스는 만들지 않습니다. 기존 ntfy는 휴대폰 수신 확인 전까지 기존 설정 그대로 유지합니다.
