# V26 사용자 버튼 관리 버전

## 실행

실행 파일 ZIP은 모두 압축 해제한 뒤 **V26Macro.exe**를 더블클릭하세요. Python 설치나 start.bat 실행이 필요 없습니다. `_internal`과 `assets` 폴더는 EXE와 함께 보관하고, 바탕화면에는 EXE의 바로가기를 만드세요. 설정 저장을 위해 쓰기 가능한 일반 폴더에서 사용하세요.

LDPlayer와 게임을 실행하고 ADB 경로 및 장치를 확인하세요. 게임의 타격 OFF / 투구 ON / 풀 플레이는 직접 설정합니다.

## GitHub 자동 업데이트

배포 저장소는 https://github.com/gy7604/compya 입니다. 실행 후 백그라운드에서 최신 정식 릴리스를 확인합니다. 새 버전이 있으면 상단에 표시되고 **업데이트 설치**로 다운로드·검증·교체·재실행합니다. 매크로를 중지하고 버튼 관리 창을 닫은 상태에서 설치하세요. 확인에 실패해도 매크로는 계속 사용할 수 있습니다.

설치할 때 `buttons.json`, `rules.json`, `last_settings.json`, `assets` 안의 기존 이미지, 로그는 유지합니다. 실행 파일과 실행 환경만 교체하고 이전 실행 파일은 `.updates/backup_...`에 보관합니다. 다운로드 오류나 해시 검증 실패는 기존 설치를 변경하지 않습니다. 파일 교체 실패 시 기존 실행 파일로 되돌립니다. 다운로드 중에는 창을 열어 두세요. 자동 확인은 로그인과 토큰이 필요 없습니다.

업데이트 기능이 없는 구버전은 이번 버전을 한 번 직접 받아야 합니다. 별도 폴더에 압축 해제한 뒤 구버전의 `buttons.json`, `rules.json`, `last_settings.json`, `assets`를 새 폴더로 복사하면 등록 내용을 이어서 사용할 수 있습니다. 배포 파일에는 개인 설정·로그·직접 등록한 이미지를 넣지 않습니다.

## 버튼을 직접 추가하기

1. 매크로 중지 → **버튼 관리 · 추가 / 수정 / 이미지 교체** → **버튼 추가**.
2. 중복되지 않는 버튼 이름을 입력합니다.
3. 게임에서 원하는 버튼이 보이게 한 뒤 **게임 화면 캡처 / 이미지 교체**를 누릅니다.
4. 캡처 창에서 버튼 전체를 드래그 → **선택 영역 저장 및 적용**.
5. **현재 화면 인식 테스트 (클릭 없음)**으로 점수와 좌표를 확인합니다.
6. **이 이미지 사용**을 체크 → 수정 창의 **저장**으로 확정합니다.

버튼 이름, 사용 여부, 인식 기준, 검색 영역, 클릭 후 최소 간격, 버튼 사라짐 제한을 각각 설정할 수 있습니다. 새 이미지는 기본 OFF입니다. 용도는 일반 클릭 / 감지 전용 / 규칙 전용 클릭 중 선택합니다. **위로 ↑ / 아래로 ↓**로 우선순위를 바꿉니다. 동시에 보이는 일반 클릭 버튼은 위에 있는 것부터 처리합니다. 기존에 등록한 이미지는 일반 클릭으로 유지됩니다.

## 목표 달성 시 시뮬레이션 전환 규칙

1. **조건 규칙 관리 → 목표 달성 → 시뮬레이션 예시 만들기**를 누릅니다. 규칙과 필요한 이미지 5개가 기본 OFF로 만들어집니다.
2. 이 창을 닫고 **버튼 관리**에서 다음 이미지를 각각 캡처하고 사용을 켭니다.
   - 목표 달성 조건: **감지 전용**. 달성 표시만 인식하고 누르지 않습니다.
   - 일시정지 / 시뮬레이션 / 확인: **규칙 전용 클릭**. 일반 동작 중에는 누르지 않습니다.
   - 시뮬레이션 진행 확인: **감지 전용**. 전환이 끝난 상태에서만 보이는 표시를 등록합니다.
3. 조건 규칙을 수정해 실제 게임 순서와 맞는지 확인합니다. 단계 추가/수정/위아래 이동/삭제가 가능합니다. 실제 화면 순서는 아직 확인되지 않았으므로 다르면 직접 바꾸세요.
4. 예시는 각 클릭 후 **다음 단계 / 최종 이미지 나타남**으로 확인합니다. 이 방식은 다음 이미지가 클릭 전에 이미 보였으면 통과하지 않고, 미감지 이후 3프레임 연속 인식될 때 확인합니다. 클릭 후 없어지는 버튼은 **이 버튼 사라짐**을 선택할 수 있습니다.
5. 규칙 사용을 켜고 저장한 뒤 **모의 실행**으로 테스트합니다. 각 모의 탭 로그가 나오면 게임에서 그 버튼을 직접 눌러 화면을 넘겨 주세요.
6. 확인 후 실제 실행으로 전환합니다. 기본은 실행당 한 번이며, 최종 이미지 확인 후 매크로를 중지합니다. 게임의 시뮬레이션은 계속 진행할 수 있습니다.

기존에 등록한 `달성`이 클릭 대상이 아닌 상태 표시라면 버튼 수정에서 **감지 전용**으로 바꾸고 규칙의 시작 조건으로 선택하세요. 예시에서 만든 빈 조건 이미지 대신 기존 이미지를 재사용할 수 있습니다.

규칙은 위에 있는 것부터 확인하며 일반 클릭보다 우선합니다. 이미 전송한 일반 클릭이 있으면 사라짐을 확인한 뒤 규칙을 시작합니다. 규칙 중에는 다른 일반 클릭을 하지 않으며, 현재 단계의 버튼만 3프레임 연속 인식한 뒤 한 번 누릅니다. 단계 대기 제한은 기본 30초입니다. 사라짐 확인 단계는 버튼별 사라짐 제한을 사용합니다. 실패하면 규칙 이름과 단계가 로그에 표시되고 안전 중지합니다.

최종 이미지는 선택 사항이지만 생략하면 최종 화면을 검증하지 않고 단계 완료만 기록합니다. 마지막 단계에서 다음 이미지 확인을 사용하면 최종 이미지는 필수입니다. `실행당 한 번만`을 끄면 규칙 완료 후 조건 이미지가 3프레임 사라졌다가 다시 3프레임 나타나야 재실행합니다. 완료 후 일반 클릭 재개도 선택할 수 있습니다.

목표 달성 여부와 시뮬레이션 전환은 사용자가 등록한 이미지로만 판단합니다. 게임에 맞는 템플릿 등록과 실제 화면 검증은 별도로 필요합니다. 예시는 자동으로 활성화하지 않습니다.

## 게임 업데이트 후 이미지 수정

목록에서 버튼을 선택 → **선택 수정 / 재캡처** → **게임 화면 캡처 / 이미지 교체**로 새 이미지를 등록합니다. 수정 창에서도 **저장**을 눌러야 최종 적용됩니다. 취소하면 기존 설정과 이미지를 유지합니다. 이름과 사용 여부는 다시 설정할 필요가 없습니다.

**PNG 불러오기**로 이미 잘라 둔 버튼 이미지를 가져올 수도 있습니다. 이미지는 프로그램 폴더로 복사됩니다. 전체 게임 화면이 아닌 버튼 이미지를 선택하세요. 불러오기는 검색 영역을 전체 화면으로 초기화합니다. **이미지 보기**에서 현재 등록 이미지를 확인합니다.

**사용 / 해제**는 이미지와 설정을 유지하면서 인식 대상에서 포함·제외합니다. **선택 삭제**는 목록에서 제거하며 저장된 이미지 파일은 지우지 않습니다.

## 저장과 이전 설정

- 버튼 목록은 `buttons.json`, 조건 규칙은 `rules.json`, 직접 등록한 이미지는 `assets/buttons`, 공통 설정은 `last_settings.json`에 저장됩니다. 폴더 전체를 함께 백업하세요.
- 캡처/불러오기로 등록한 이미지는 상대 경로로 저장되어 프로그램 폴더 전체를 옮겨도 유지됩니다.
- `buttons.json`이 없으면 첫 실행 때 기존 포수 리드와 PLAY BALL 설정을 자동 변환합니다. 이후에는 버튼 목록을 우선합니다.
- 이전 버전에서 옮길 때는 종료 후 기존 `last_settings.json`과 `assets` 폴더를 새 폴더로 복사하세요. 외부 이미지 경로를 사용했다면 원본을 유지하거나 다시 등록하세요.
- 배포 기본값은 포수 리드 사용 / PLAY BALL 이미지 미등록입니다. 게임 모드 확인과 모의 실행 체크는 실행할 때마다 초기화합니다.

## 인식과 안전장치

사용 중인 버튼 하나가 3프레임 연속 인식되면 이미지 중앙을 한 번 클릭합니다. 클릭한 버튼이 3프레임 연속 인식되지 않아야 다음 클릭을 허용합니다. 일반 클릭 대상이 동시에 인식되면 목록의 위쪽 버튼을 선택하고, 선택한 대상이 3프레임 연속 유지되어야 누릅니다. 감지 전용 이미지는 절대 클릭하지 않으며 규칙 전용 클릭은 해당 단계에서만 누릅니다.

버튼별 기본 인식 기준은 0.90, 클릭 후 최소 간격은 2초, 사라짐 제한은 8초입니다. 최소 간격은 해당 클릭 후 다른 버튼을 포함한 다음 클릭까지 적용됩니다. 사라짐 확인은 이미지 인식 결과를 기준으로 하므로 고정된 모양과 글자를 포함해 등록하세요. 단색 영역과 너무 작은 선택은 거부합니다. 템플릿 매칭은 비슷한 다른 화면을 완전히 구별하지 못합니다.

검색 영역은 ADB 원본 화면의 `x,y,너비,높이`입니다. 캡처 등록 시 선택 영역 주위 25픽셀 여백으로 자동 설정합니다. 위치가 바뀌면 다시 캡처하거나 영역을 수정하세요. 캡처한 해상도와 현재 해상도가 다르면 중지합니다. PNG 불러오기는 캡처 해상도 정보가 없어 시작 시 해상도 비교를 하지 않습니다.

ADB 연결/5초 호출 시간 초과, 잘못된 PNG/검색 영역, 실행 중 해상도 변경, 버튼 사라짐 제한 초과 시 중지합니다. 인식 대기 제한은 기본 180초입니다. 자동 재시작과 실패한 탭 재전송은 없습니다. 화면 확인 간격은 ADB 처리 시간에 더해 0.25초입니다.

기본 **모의 실행**은 클릭을 보내지 않습니다. 모의 탭 로그 뒤 사라짐 제한 시간 안에 게임 버튼을 직접 눌러 흐름을 확인하세요. 확인 후 중지하고 모의 실행 체크를 해제합니다. **중지** 또는 프로그램 창에 포커스가 있을 때 **Esc**로 멈춥니다. 이미 보낸 입력은 취소할 수 없습니다. 로그는 `logs/macro.log`입니다.

시간 초과로 중지하면 버튼 이름과 사라짐 확인 상태를 표시하고, 마지막 캡처 화면을 `logs/last_stop.png`, 인식 점수와 설정을 `logs/last_stop.json`에 저장합니다. 다음 시간 초과 때 덮어쓰며 외부로 자동 전송하지 않습니다. 실제 클릭이 되지 않았거나 다른 위치가 인식되었다면 해당 버튼을 다시 캡처하세요. 화면 전환 자체가 느린 경우에만 버튼별 사라짐 제한을 늘리세요.

## 범위와 정책

이 기능은 등록한 버튼을 인식해 중앙을 누릅니다. 조건 이미지에 따른 순차 클릭 규칙을 설정할 수 있습니다. 버튼의 의미를 스스로 판단하거나 드래그, 타격 타이밍, 경기 완료 인식과 경기 수 집계를 수행하지는 않습니다. 랭킹 목표 경기 수는 UI와 설정 저장만 준비되어 있으며 자동 종료 조건이 아닙니다.

매크로 사용은 게임 운영정책·이용약관에 따라 금지되거나 계정 제재 대상일 수 있습니다. 공식 정책을 확인하고 허용된 범위에서 사용하세요. 탐지 회피·보안 우회·메모리 조작 기능은 없습니다.

## 소스와 테스트

소스 ZIP은 Python 3.11 이상과 Tkinter가 필요합니다. `setup.bat`으로 설치와 테스트, `start.bat`으로 실행합니다. 실행 파일 ZIP 사용자에게는 필요 없는 과정입니다.

`python -m unittest discover -s tests -v`로 상태 전환, 중복 방지, ADB 오류, 이미지와 좌표 인식, 버튼 저장·수정·삭제·복원·이전 설정 변환·잘못된 설정 거부, 버튼별 클릭 간격/시간 초과, 실제/모의 탭 구분을 검사합니다. 실제 게임과 LDPlayer 연동은 사용자 환경에서 확인해야 합니다.

## 다음 버전 배포하기

소스를 수정하고 `version.py`의 VERSION을 `1.0.1`처럼 올린 뒤 GitHub에 반영합니다. 저장소 **Actions → Build Windows release → Run workflow**를 실행하면 테스트·Windows 실행 파일 제작·Releases 업로드를 진행합니다. 같은 버전을 덮어쓰지 말고 새 버전 번호를 사용하세요. 사용 중인 프로그램은 새 릴리스를 확인해 설치할 수 있습니다. GitHub가 프로그램 코드를 자동으로 수정하는 기능은 아닙니다.

로컬 Windows에서 빌드하려면 `python -m pip install -r requirements-tested.txt pyinstaller==6.22.3` 후 `./build.ps1`을 실행합니다. 개인 설정, 로그, 직접 등록한 이미지는 배포 ZIP에서 자동 제외됩니다.
