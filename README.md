# V26 사용자 버튼 관리 버전

## 실행

실행 파일 ZIP은 모두 압축 해제한 뒤 **V26Macro.exe**를 더블클릭하세요. Python 설치나 start.bat 실행이 필요 없습니다. `_internal`과 `assets` 폴더는 EXE와 함께 보관하고, 바탕화면에는 EXE의 바로가기를 만드세요. 설정 저장을 위해 쓰기 가능한 일반 폴더에서 사용하세요.

LDPlayer와 게임을 실행하고 ADB 경로 및 장치를 확인하세요. 게임의 타격 OFF / 투구 ON / 풀 플레이는 직접 설정합니다.

## GitHub 자동 업데이트

배포 저장소는 https://github.com/gy7604/compya 입니다. 실행 후 백그라운드에서 최신 정식 릴리스를 확인합니다. 새 버전이 있으면 상단에 표시되고 **업데이트 설치**로 다운로드·검증·교체·재실행합니다. 매크로를 중지하고 버튼 관리 창을 닫은 상태에서 설치하세요. 확인에 실패해도 매크로는 계속 사용할 수 있습니다.

설치할 때 `buttons.json`, `rules.json`, `progress.json`, `last_settings.json`, `assets` 안의 기존 이미지, 로그는 유지합니다. 실행 파일과 실행 환경만 교체하고 이전 실행 파일은 `.updates/backup_...`에 보관합니다. 다운로드 오류나 해시 검증 실패는 기존 설치를 변경하지 않습니다. 파일 교체 실패 시 기존 실행 파일로 되돌립니다. 다운로드 중에는 창을 열어 두세요. 자동 확인은 로그인과 토큰이 필요 없습니다.

업데이트 기능이 없는 구버전은 이번 버전을 한 번 직접 받아야 합니다. 별도 폴더에 압축 해제한 뒤 구버전의 `buttons.json`, `rules.json`, `progress.json`, `last_settings.json`, `assets`를 새 폴더로 복사하면 등록 내용을 이어서 사용할 수 있습니다. 배포 파일에는 개인 설정·로그·직접 등록한 이미지를 넣지 않습니다.

## 버튼을 직접 추가하기

1. 매크로 중지 → **버튼 관리 · 추가 / 수정 / 이미지 교체** → **버튼 추가**.
2. 중복되지 않는 버튼 이름을 입력합니다.
3. 게임에서 원하는 버튼이 보이게 한 뒤 **게임 화면 캡처 / 이미지 교체**를 누릅니다.
4. 캡처 창에서 버튼 전체를 드래그 → **선택 영역 저장 및 적용**.
5. **현재 화면 인식 테스트 (클릭 없음)**으로 점수와 좌표를 확인합니다.
6. **이 이미지 사용**을 체크 → 수정 창의 **저장**으로 확정합니다.

버튼 이름, 사용 여부, 인식 기준, 검색 영역, 클릭 후 최소 간격, 규칙용 버튼 사라짐 제한을 각각 설정할 수 있습니다. 새 이미지는 기본 OFF입니다. 용도는 일반 클릭 / 감지 전용 / 규칙 전용 클릭 중 선택합니다. **위로 ↑ / 아래로 ↓**로 우선순위를 바꿉니다. 동시에 보이는 일반 클릭 버튼은 위에 있는 것부터 처리합니다. 기존에 등록한 이미지는 일반 클릭으로 유지됩니다.

## 이닝 교대·비디오판독 등을 넘기는 진행 보조 클릭

1. 매크로를 중지한 뒤 메인 창의 **진행 보조 클릭 설정**을 엽니다.
2. 미인식을 확인할 이미지 두 개를 **PlayBall / 포수리드**로 선택합니다. 해당 이미지는 버튼 관리에서 등록하고 사용을 켜야 합니다.
3. **화면에서 보조 클릭 위치 선택**으로 경기 화면의 여백 등 실제로 누를 곳을 선택합니다. 메뉴·확인·재화 사용 버튼과 겹치지 않는 지점을 직접 정하세요. 좌표 선택 자체는 게임 입력을 보내지 않습니다.
4. 기본 **미인식 대기 3초 / 반복 간격 5초**를 확인하고 **진행 보조 클릭 사용**을 체크한 뒤 저장합니다.
5. 모의 실행에서 `모의 보조 탭` 로그를 확인하고 실제 실행으로 전환하세요.

선택한 두 이미지가 모두 인식되지 않는 상태가 최소 3회 캡처 및 지정 시간 동안 유지되면 보조 좌표를 누릅니다. 계속 미인식이면 지정한 간격으로 반복하며, 둘 중 하나라도 인식되면 대기 시간을 초기화하고 보조 클릭을 멈춥니다.

일반 클릭 버튼이 인식되거나 이전 클릭의 사라짐 대기, 최소 클릭 간격 대기, 조건 규칙 예약/실행 중에는 보조 클릭을 보류하고 대기 시간을 초기화합니다. 일반 버튼과 규칙이 우선입니다. 실제 이벤트 종류를 판단하는 기능은 아니므로, 두 이미지가 없는 다른 화면에서도 조건을 만족하면 보조 좌표를 누를 수 있습니다. 감시 이미지가 잘못 인식되면 보조 클릭 조건도 맞게 판단할 수 없습니다.

보조 설정은 **기본 OFF**, `progress.json`에 저장되며 업데이트 때 유지합니다. 등록한 좌표의 해상도가 현재 화면과 다르면 중지합니다. 직접 중지하거나 규칙의 완료 후 중지로 매크로가 끝나면 보조 클릭도 끝납니다.

## 이미지 감지와 클릭 위치 분리

버튼 관리에서 항목을 수정하면 **클릭 위치**를 선택할 수 있습니다.

1. 매크로를 중지한 뒤 PLAY BALL 등 원하는 항목을 수정합니다.
2. **화면에서 클릭 위치 선택**을 누릅니다. ADB 캡처 창에서 실제 누를 버튼의 중앙을 한 번 선택하세요. 이 선택 자체는 게임에 탭을 보내지 않습니다.
3. **이 좌표 사용**을 누르면 원본 화면의 X,Y와 해상도가 기록되고 **지정 좌표** 모드가 됩니다. 숫자를 직접 수정할 수도 있습니다.
4. **현재 화면 인식 테스트 (클릭 없음)**에서 인식 이미지의 중앙과 실제 클릭 예정 좌표를 비교하세요.
5. 수정 창의 **저장** 후 다시 시작합니다.

등록한 이미지가 인식되어 클릭 가능한 차례가 되면, 이미지가 발견된 위치와 관계없이 지정 좌표로 ADB 탭을 보냅니다. 기존 항목은 **인식한 이미지 중앙** 방식을 유지합니다. 지정 좌표는 일반 클릭과 규칙 전용 클릭 모두 지원하며, 감지 전용 이미지는 클릭하지 않습니다.

X,Y는 LDPlayer 창 바깥 테두리나 Windows 바탕화면 좌표가 아닌 **ADB 게임 원본 화면 좌표**입니다. 해상도가 바뀌면 클릭 위치를 다시 선택해야 하며, 화면 밖 좌표에는 입력하지 않습니다. 업데이트 시 좌표도 버튼 설정과 함께 보존됩니다.

기준 점수 0.5는 버튼이 없는 화면도 인식할 수 있습니다. 지정 좌표 기능이 오인식 자체를 해결하는 것은 아니므로 인식 테스트로 대상이 맞는지 확인하세요. 이전 클릭의 사라짐 대기, 우선순위, 규칙 실행, 최소 클릭 간격은 유지됩니다. 로그에 점수와 기준값, 실제/모의 실행 구분, 인식 위치, 실제 탭 위치, 사라짐 확인 횟수를 표시합니다.

## 목표 달성 시 시뮬레이션 전환

1. **조건 규칙 관리 → 목표 달성 → 시뮬레이션 예시 만들기**를 누릅니다. 규칙과 필요한 이미지 5개가 기본 OFF로 만들어집니다.
2. 이 창을 닫고 **버튼 관리**에서 다음 이미지를 각각 캡처하고 사용을 켭니다.
   - 목표 달성 조건: **감지 전용**. 달성 표시만 인식하고 누르지 않습니다.
   - 일시정지 / 시뮬레이션 / 확인: **규칙 전용 클릭**. 일반 동작 중에는 누르지 않습니다.
   - 시뮬레이션 진행 확인: **감지 전용**. 전환이 끝난 상태에서만 보이는 표시를 등록합니다.
3. 조건 규칙을 수정해 실제 게임 순서와 맞는지 확인합니다. 단계 추가/수정/위아래 이동/삭제가 가능합니다. 실제 화면 순서는 아직 확인되지 않았으므로 다르면 직접 바꾸세요.
4. 예시는 각 클릭 후 **다음 단계 / 최종 이미지 나타남**으로 확인합니다. 이 방식은 다음 이미지가 클릭 전에 이미 보였으면 통과하지 않고, 미감지 이후 3프레임 연속 인식될 때 확인합니다. 클릭 후 없어지는 버튼은 **이 버튼 사라짐**을 선택할 수 있습니다.
5. 규칙 사용을 켜고 저장한 뒤 **모의 실행**으로 테스트합니다. 각 모의 탭 로그가 나오면 게임에서 그 버튼을 직접 눌러 화면을 넘겨 주세요.
6. 확인 후 실제 실행으로 전환합니다. 기본은 실행당 한 번이며, 최종 이미지 확인 후 매크로를 중지합니다. 게임의 시뮬레이션은 계속 진행할 수 있습니다.

기존에 등록한 `달성`이 클릭 대상이 아닌 상태 표시라면 버튼 수정에서 **감지 전용**으로 바꾸고 규칙의 시작 조건으로 선택하세요. 예시에서 만든 빈 조건 이미지 대신 기존 이미지를 재사용할 수 있습니다.

규칙은 위에 있는 것부터 확인하며 일반 클릭보다 우선합니다. 이미 전송한 일반 클릭이 있으면 사라짐을 확인한 뒤 규칙을 시작합니다. 규칙 중에는 다른 일반 클릭을 하지 않으며, 현재 단계의 버튼만 선택한 반응속도의 연속 인식 횟수를 충족한 뒤 한 번 누릅니다. 단계 대기 제한은 기본 30초입니다. 사라짐 확인 단계는 버튼별 사라짐 제한을 사용합니다. 실패하면 규칙 이름과 단계가 로그에 표시되고 안전 중지합니다.

최종 이미지는 선택 사항이지만 생략하면 최종 화면을 검증하지 않고 단계 완료만 기록합니다. 마지막 단계에서 다음 이미지 확인을 사용하면 최종 이미지는 필수입니다. `실행당 한 번만`을 끄면 규칙 완료 후 조건 이미지가 3프레임 사라졌다가 다시 3프레임 나타나야 재실행합니다. 완료 후 일반 클릭 재개도 선택할 수 있습니다.

목표 달성 여부와 시뮬레이션 전환은 사용자가 등록한 이미지로만 판단합니다. 게임에 맞는 템플릿 등록과 실제 화면 검증은 별도로 필요합니다. 예시는 자동으로 활성화하지 않습니다.

## 게임 업데이트 후 이미지 수정

목록에서 버튼을 선택 → **선택 수정 / 재캡처** → **게임 화면 캡처 / 이미지 교체**로 새 이미지를 등록합니다. 수정 창에서도 **저장**을 눌러야 최종 적용됩니다. 취소하면 기존 설정과 이미지를 유지합니다. 이름과 사용 여부는 다시 설정할 필요가 없습니다.

**PNG 불러오기**로 이미 잘라 둔 버튼 이미지를 가져올 수도 있습니다. 이미지는 프로그램 폴더로 복사됩니다. 전체 게임 화면이 아닌 버튼 이미지를 선택하세요. 불러오기는 검색 영역을 전체 화면으로 초기화합니다. **이미지 보기**에서 현재 등록 이미지를 확인합니다.

**사용 / 해제**는 이미지와 설정을 유지하면서 인식 대상에서 포함·제외합니다. **선택 삭제**는 목록에서 제거하며 저장된 이미지 파일은 지우지 않습니다.

## 저장과 이전 설정

- 버튼 목록은 `buttons.json`, 조건 규칙은 `rules.json`, 진행 보조 설정은 `progress.json`, 직접 등록한 이미지는 `assets/buttons`, 공통 설정은 `last_settings.json`에 저장됩니다. 폴더 전체를 함께 백업하세요.
- 캡처/불러오기로 등록한 이미지는 상대 경로로 저장되어 프로그램 폴더 전체를 옮겨도 유지됩니다.
- `buttons.json`이 없으면 첫 실행 때 기존 포수 리드와 PLAY BALL 설정을 자동 변환합니다. 이후에는 버튼 목록을 우선합니다.
- 이전 버전에서 옮길 때는 종료 후 기존 `last_settings.json`과 `assets` 폴더를 새 폴더로 복사하세요. 외부 이미지 경로를 사용했다면 원본을 유지하거나 다시 등록하세요.
- 배포 기본값은 포수 리드 사용 / PLAY BALL 이미지 미등록입니다. 게임 모드 확인과 모의 실행 체크는 실행할 때마다 초기화합니다.

## 인식과 안전장치

메인 창의 **인식 반응속도**에서 빠름 / 균형 / 안정적을 선택합니다.

- **빠름 · 1회 인식**: 화면에서 기준 점수 이상으로 한 번 인식하면 클릭합니다. 캡처 사이의 인위적인 대기 시간은 없습니다.
- **균형 · 2회 확인**: 2회 연속 인식하며 캡처 처리 후 0.10초 대기합니다.
- **안정적 · 3회 확인**: 기존과 같은 3회 확인과 0.25초 대기를 유지합니다. 기존 설정을 이어받을 때 기본값입니다.

설정은 일반 클릭, 조건 이미지 감지, 규칙 단계 버튼의 첫 인식에 적용합니다. 클릭 후 사라짐, 다음 화면과 최종 이미지 확인은 모드에 관계없이 3회를 유지합니다. 버튼별 최소 클릭 간격도 유지합니다. 해당 간격은 버튼 관리에서 조정할 수 있습니다. 빠름은 짧은 오인식에도 반응하므로 템플릿과 검색 영역을 인식 테스트로 확인하세요.

빠름도 ADB 화면 캡처·전송, 이미지 비교, 탭 전송 시간은 필요합니다. 화면을 직접 스트리밍하는 방식은 아니므로 게임 화면의 변화와 완전히 동시에 클릭한다고 보장할 수 없습니다.

선택한 반응속도의 확인 횟수만큼 인식되면 이미지 중앙을 한 번 클릭합니다. 클릭한 버튼이 3프레임 연속 인식되지 않아야 다음 클릭을 허용합니다. 일반 클릭 대상이 동시에 인식되면 목록의 위쪽 버튼을 선택하고, 선택한 대상이 반응속도 설정의 확인 횟수만큼 유지되어야 누릅니다. 감지 전용 이미지는 절대 클릭하지 않으며 규칙 전용 클릭은 해당 단계에서만 누릅니다.

버튼별 기본 인식 기준은 0.90, 클릭 후 최소 간격은 2초, 규칙 단계의 사라짐 제한은 8초입니다. 일반 클릭에는 사라짐 시간 제한이 없습니다. 최소 간격은 해당 클릭 후 다른 버튼을 포함한 다음 클릭까지 적용됩니다. 사라짐 확인은 이미지 인식 결과를 기준으로 하므로 고정된 모양과 글자를 포함해 등록하세요. 단색 영역과 너무 작은 선택은 거부합니다. 템플릿 매칭은 비슷한 다른 화면을 완전히 구별하지 못합니다.

검색 영역은 ADB 원본 화면의 `x,y,너비,높이`입니다. 캡처 등록 시 선택 영역 주위 25픽셀 여백으로 자동 설정합니다. 위치가 바뀌면 다시 캡처하거나 영역을 수정하세요. 캡처한 해상도와 현재 해상도가 다르면 중지합니다. PNG 불러오기는 캡처 해상도 정보가 없어 시작 시 해상도 비교를 하지 않습니다.

ADB 연결/5초 호출 시간 초과, 잘못된 PNG/검색 영역, 실행 중 해상도 변경, 조건 규칙의 단계 제한 초과 시 중지합니다. 일반 버튼을 찾지 못하거나 클릭한 일반 버튼이 계속 보여도 시간 초과로 중지하지 않고 화면을 계속 확인합니다. 중복 클릭은 하지 않으며 클릭한 버튼이 3프레임 사라져야 다음 클릭을 허용합니다. 기존 180초 인식 대기 설정은 사용하지 않습니다. 자동 재시작과 실패한 탭 재전송은 없습니다. 화면 확인 간격은 ADB 처리 시간에 반응속도 모드의 추가 대기 시간이 더해집니다.

기본 **모의 실행**은 클릭을 보내지 않습니다. 모의 탭 로그 뒤 게임 버튼을 직접 눌러 흐름을 확인하세요. 조건 규칙의 단계 제한은 모의 실행에도 적용됩니다. 확인 후 중지하고 모의 실행 체크를 해제합니다. **중지** 또는 프로그램 창에 포커스가 있을 때 **Esc**로 멈춥니다. 이미 보낸 입력은 취소할 수 없습니다. 로그는 `logs/macro.log`입니다.

조건 규칙의 시간 초과로 중지하면 규칙/단계 이름과 인식 상태를 표시하고, 마지막 캡처 화면을 `logs/last_stop.png`, 인식 점수와 설정을 `logs/last_stop.json`에 저장합니다. 다음 시간 초과 때 덮어쓰며 외부로 자동 전송하지 않습니다. 실제 클릭이 되지 않았거나 다른 위치가 인식되었다면 해당 버튼을 다시 캡처하세요. 화면 전환 자체가 느린 경우에만 버튼별 사라짐 제한을 늘리세요.

## 범위와 정책

이 기능은 등록한 이미지를 인식해 이미지 중앙 또는 지정 좌표를 누릅니다. 조건 이미지에 따른 순차 클릭 규칙을 설정할 수 있습니다. 버튼의 의미를 스스로 판단하거나 드래그, 타격 타이밍, 경기 완료 인식과 경기 수 집계를 수행하지는 않습니다. 랭킹 목표 경기 수는 UI와 설정 저장만 준비되어 있으며 자동 종료 조건이 아닙니다.

매크로 사용은 게임 운영정책·이용약관에 따라 금지되거나 계정 제재 대상일 수 있습니다. 공식 정책을 확인하고 허용된 범위에서 사용하세요. 탐지 회피·보안 우회·메모리 조작 기능은 없습니다.

## 소스와 테스트

소스 ZIP은 Python 3.11 이상과 Tkinter가 필요합니다. `setup.bat`으로 설치와 테스트, `start.bat`으로 실행합니다. 실행 파일 ZIP 사용자에게는 필요 없는 과정입니다.

`python -m unittest discover -s tests -v`로 상태 전환, 중복 방지, ADB 오류, 이미지와 좌표 인식, 버튼 저장·수정·삭제·복원·이전 설정 변환·잘못된 설정 거부, 버튼별 클릭 간격/시간 초과, 실제/모의 탭 구분을 검사합니다. 실제 게임과 LDPlayer 연동은 사용자 환경에서 확인해야 합니다.

## 다음 버전 배포하기

소스를 수정하고 `version.py`의 VERSION을 `1.0.1`처럼 올린 뒤 GitHub에 반영합니다. 저장소 **Actions → Build Windows release → Run workflow**를 실행하면 테스트·Windows 실행 파일 제작·Releases 업로드를 진행합니다. 같은 버전을 덮어쓰지 말고 새 버전 번호를 사용하세요. 사용 중인 프로그램은 새 릴리스를 확인해 설치할 수 있습니다. GitHub가 프로그램 코드를 자동으로 수정하는 기능은 아닙니다.

로컬 Windows에서 빌드하려면 `python -m pip install -r requirements-tested.txt pyinstaller==6.22.3` 후 `./build.ps1`을 실행합니다. 개인 설정, 로그, 직접 등록한 이미지는 배포 ZIP에서 자동 제외됩니다.

## 휴대폰 알림 (ntfy · v1.4.0)

Android에 ntfy 앱을 설치하고 알림 권한을 허용하세요. 매크로를 중지한 뒤 **휴대폰 알림 설정**을 엽니다. 자동 생성된 긴 채널 이름을 휴대폰 ntfy의 + 버튼에서 그대로 구독합니다. 서버는 https://ntfy.sh 입니다. **휴대폰으로 테스트 알림 보내기**로 실제 수신을 확인하세요. 휴대폰 앱의 알림/배터리 설정에 따라 지연될 수 있으며 즉시 수신을 보장하지 않습니다.

버튼 관리에서 알림용 이미지를 캡처하고 종류를 감지 전용, 사용 ON으로 설정한 뒤 알림 설정에서 선택합니다. 여러 이미지 선택, 메시지, 감지 후 중지 여부를 설정하고 사용을 켜서 저장하세요. 3회 연속 인식 시 한 번 전송하고 3회 연속 사라진 뒤 재등장하면 재전송합니다. 매크로를 다시 시작하면 감지 이력이 초기화됩니다. 모의 실행은 로그만 남기며 자동 알림을 보내지 않습니다. 테스트 버튼은 실제로 전송합니다.

알림 후 중지를 켜면 이미지 감지 확인 중 클릭을 보류하고 3회 인식 후 클릭 전에 중지합니다. 전송 실패 시에도 중지합니다. 전송은 별도 작업으로 수행하며 최대 8초 후 실패 처리하고 자동 재시도하지 않습니다. 테스트 성공 표시는 서버 접수 성공이며 휴대폰 수신 보장은 아닙니다. 프로그램을 즉시 종료하면 전송 중인 알림이 취소될 수 있습니다.

공개 ntfy.sh의 익명 채널은 이름을 아는 사람이 구독·발송할 수 있습니다. 긴 무작위 채널을 사용하고 채널 이름과 개인정보를 공유하지 마세요. 메시지와 감지한 이미지 이름만 서버로 전송하며 스크린샷은 보내지 않습니다. PC 인터넷 연결이 필요합니다. notifications.json은 개인 설정으로 GitHub와 배포 ZIP에서 제외되며 업데이트 시 보존됩니다.

규칙의 **최종 확인 이미지**에는 마지막 클릭 후 나타날 화면을 지정하세요. 확인을 누르면 사라지는 알림을 지정하면 그 알림이 다시 나타나길 기다리다 중지됩니다. 마지막 버튼 사라짐만 확인하고 일반 동작을 재개하려면 최종 확인 이미지를 미지정으로 두고 마지막 단계는 이 버튼 사라짐, 완료 후 일반 동작 재개로 설정합니다.


## v1.4.1 조건 규칙 시간 제한 제거

일반 클릭뿐 아니라 조건 규칙의 버튼 나타남, 버튼 사라짐, 다음 이미지, 최종 이미지 확인도 시간 제한 없이 기다립니다. 기존 설정 파일의 timeout/disappear_timeout 값은 호환을 위해 보존되지만 실행 중 자동 중지에 사용하지 않습니다. 설정 화면의 시간 제한 입력은 제거했습니다. 최소 클릭 간격, 연속 인식, 중복 클릭 방지는 유지합니다. 잘못된 최종 이미지를 선택하면 계속 대기하므로 해당 규칙을 수정해야 합니다. 규칙 완료 후 중지, 알림 감지 후 중지, ADB/화면/좌표 오류, 직접 중지는 유지됩니다.
