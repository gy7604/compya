# 컴프야: 빌드와 승인 후 게시

일반채팅은 비공개 TeslaSafety #105에서 기존 요청형 Windows 빌드를 사용한다. 새 게시 경로는 공개 compya #3이며 앱 코드를 다시 빌드하거나 실행하지 않는다. 이전 `release.yml`은 비활성을 유지한다. PC 어댑터는 아직 별도 등록 전이다.

1. 비공개 후보의 정확한 요청 ID·소스 SHA·버전·테스트 수·ZIP 해시와 원래 후보 보관 위치를 확인한다. 현재 공개 버전보다 높은 버전이어야 한다. 같은 버전 재게시·자동 재빌드는 하지 않는다.
2. 사용자에게 변경 내용, 수행/미수행 검사, 후보 해시, 현재 공개 버전과 기존 업데이트 대상을 보여 주고 **그 버전의 공개 배포 승인을 받는다**. 자동화 준비·계속·빌드 승인을 배포 승인으로 대신하지 않는다.
3. 승인 전에는 비공개 후보나 접근 URL을 공개 이슈로 옮기지 않는다. 비공개 제어 큐의 성공 영수증, 고정된 `candidate.py`의 산출물 두 파일만 보관하는 코드, 원본 소유자 빌드 요청과 연결된 실행 ID를 확인한다. GitHub `fetch_workflow_run_artifacts`의 이름·실행·만료·서버 `digest`를 읽는다. 정확한 실행의 단일 후보/영수증 ZIP만 사용하며 진단 로그용 아티팩트는 전달하지 않는다. 바이트 검사 수단이 있으면 `inspect_bundle`도 먼저 실행한다. 없으면 서버 digest와 신뢰된 패키징 증거로 대상을 고정하고, 공개 작업이 바이트와 영수증을 실제 검증한 뒤에만 Release에 올리도록 한다. 이 구분을 검사 보고에 남긴다.
4. GitHub 도구의 `file_uri.download_url` 또는 `structuredContent.download_url`을 메모리에서만 재사용한다. 공개 승인을 받은 그 파일에 대한 단기 접근값이며, 다른 계정 토큰은 사용하지 않는다. 로그나 안내 문서에 URL을 복사하지 않는다.
5. 공개 compya #3에 소유자 GitHub 연결로 다음 명령을 등록한다. 사용자가 외워서 입력할 필요는 없다.

   `/compya-publish approve REQUEST_ID SOURCE_SHA VERSION OUTER_ZIP_SHA256 CURRENT_RELEASE_ID APPROVED_FILE_URL`

6. 게시 작업은 15분 이내 원본 승인, 최신 공개 release ID, 버전 증가, 후보/영수증/파일 해시와 경로를 검사한다. 비공개 소스를 실행하지 않고 기존 ZIP만 draft에 올린다. draft의 서버 해시를 확인한 뒤 같은 승인을 다시 검사하고 공개한다. 공개 실패·모호한 결과·이미 사용한 버전은 자동 재시도하거나 draft를 덮어쓰지 않는다.
7. 공개 최신 다운로드의 해시와 앱 내 업데이트 규약을 확인한다. 사용자 PC 설치·실제 게임 동작·Authenticode는 이 게시만으로 검증됐다고 보고하지 않는다. 사용자 설정과 기존 업데이트 백업은 보존한다.

로컬 합성 검사 4개 통과. 실제 새 버전 게시/앱 내 업데이트는 이번 준비에서 실행하지 않았다. 현재 공개 2.0.10 후보를 다시 게시하지 않는다.
